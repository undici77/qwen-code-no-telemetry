# 前缀稳定的工具轮次

[English](prefix-stable-tool-turns.md) | [简体中文](prefix-stable-tool-turns.zh-CN.md)

状态：已在分支 `feat/prefix-stable-tool-turns` 上实现（no-telemetry 分支，§14 扩展）。已通过单元测试验证；oMLX 实机验证待完成。

## 问题

在本地前缀缓存服务器（oMLX、vLLM）上执行较长的智能体轮次时，服务器会在一个轮次内多次重新预填充大部分上下文，通常发生在每次写入记忆之后。即使设置了 `QWEN_MEMORY_APPEND_ONLY=1` 并在设置中禁用了工具搜索，问题依然存在。

## 现状

- 上游 #13521 已将记忆索引移出系统提示词。目录现在以追加的"完整快照"部分（`memory/request-context.ts`）传递，因此写入记忆不再改变系统提示词、工具列表或 `history[0]`。
- 在工具结果轮次中，上游会在 `functionResponse` 部分之后追加注入的上下文：`MEMORY.md` 变更后的目录快照、每三个工具轮次一次的待办提醒、记忆召回，以及循环/探索提醒。
- OpenAI 转换器把这些文本作为单独的 `role: "user"` 消息，放在工具消息之后发出。
- Qwen/DeepSeek 风格的聊天模板只为最后一条用户消息之后的助手消息渲染 `<think>`。因此，轮次中途注入的用户消息会让本轮所有更早步骤的推理从渲染后的提示词中消失。第一个不同的 token 退回到本轮第一条助手消息，服务器从那里开始重新预填充。
- Anthropic 转换器没有这个问题：它已经把这类文本合并进 `tool_result` 消息。
- 分支原有的 §14 增量在一批工具执行完、但其响应尚未提交时通过 `addHistory` 加入，导致工具调用和其结果之间夹了一个用户轮次。

## 目标

- 设置 `QWEN_MEMORY_APPEND_ONLY` 后，即使有注入的上下文，工具步骤 N+1 的渲染提示词也是步骤 N 的延续。
- 未设置该标志时，OpenAI 线上格式与上游逐字节一致。
- 绝不把真实的用户提示隐藏在工具结果里。

## 非目标

- 真实用户提示之间的推理丢失。这是模板行为；对支持的模板，用设置配方（`preserve_thinking`）解决。
- 标志开启时对 `QWEN.md` 写入的传递（后续处理）。

## 设计

### 将注入的上下文折叠进最后一条工具消息

`foldInjectedContextIntoToolMessage`（分支自有，`core/openaiContentGenerator/tool-turn-reminder-fold.ts`）在 `processContent` 原本要发出本轮末尾用户消息的位置运行。仅当以下条件全部满足时才折叠：

1. 标志已开启。
2. 本轮至少发出了一条工具消息。
3. 没有工具媒体被拆分到后续用户消息。
4. 每个文本部分都是注入的上下文：携带 `AUTO_MEMORY_SNAPSHOT_METADATA`，或以 `SYSTEM_REMINDER_OPEN` 开头。

满足时，这些文本被追加到最后一条工具消息（字符串内容用 `\n\n` 连接，数组内容作为文本部分追加），并且不再发出单独的用户消息。

规则是"全有或全无"，因为 `extractCuratedHistory` 会合并相邻的用户条目，中断后输入的提示可能与工具结果处于同一轮次。只要有一个无法识别的文本部分，整轮就保持上游路径。最坏情况是错过一次缓存命中，绝不会隐藏用户文本。

### 在用户查询边界传递 §14 增量

`appendAutoMemoryDelta` 现在只从磁盘重新加载记忆。`drainAutoMemoryDelta` 计算增量并追加，它在 `client.ts` 现有的 `!hasPendingToolCall && (UserQuery || Cron)` 排空块中调用，也就是上游排空延迟 MCP 提醒的同一位置。因此增量总是紧挨在真实用户提示之前落地，而那里本来就是模板边界。

## 决策与理由

| 决策                                          | 理由                                                                                     |
| --------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 复用现有的 `QWEN_MEMORY_APPEND_ONLY` 作为开关 | 只有一个提示词缓存开关；标志关闭 ⇒ 与上游一致。                                          |
| 只识别快照和 `<system-reminder>` 文本         | 不会误判用户文本；未包装的上游提醒保持上游行为。                                         |
| 挂在转换器中，而不是历史中                    | 历史和录制保持不变；折叠是存储历史的纯确定性函数，因此每次请求对更早轮次的序列化都相同。 |
| `preserve_thinking` 只写文档                  | 它依赖模板；通用提供方已经合并 `extra_body`。                                            |

## 风险

- 模型会在工具结果中而不是用户消息中看到部分提醒。上游的 Anthropic 路径已经这样做。
- 如果上游改变某个提醒的格式，该提醒会悄悄停止折叠。代价只是缓存，不影响正确性。快照和 §14 增量有固定测试覆盖。

## 验证

- `tool-turn-reminder-fold.test.ts` 中的单元测试：
  - 标志关闭
  - 快照和提醒的折叠
  - 并行工具调用

  - 合并进工具轮次的用户文本

  - 请求 N 是请求 N+1 的前缀
  - §14 增量被识别

- 实机：在 oMLX 上按 E2E 测试计划使用 `cache-live` 状态栏项验证。

## 验收标准

- 标志开启时，对于文本全部是注入上下文的轮次，工具消息之后不再出现 `role: "user"` 消息。
- 标志关闭时，转换器输出不变。
- 门禁检查和单元测试通过。
